### 1.3 列表字段每个位置的确定解释

- `fineweb_edu`：只有位置 0，连续回归分数。
- `fluency_en`：位置 0 为“不流畅”，位置 1 为“流畅”。
- `ad_en`：位置 0 为“含广告”，位置 1 为“无广告”。
- `modernbert_cleanliness/readability/reasoning/professionalism`：位置 0、1、2、3、4、5 分别对应质量等级 0–5，列表内容是 logits，不是六个独立指标。
- `qurater`：位置 0 为写作风格，1 为所需专业知识，2 为事实与知识，3 为教育价值。四个值是四个不同评价头，不能取 `argmax`，也不能把位置当等级。

对初学者最重要的区别：`modernbert_*` 的六个数是在回答“属于哪个等级”，而 `qurater` 的四个数是在回答“四个不同问题”。

### 1.4 可供队伍选择的指标表示方法

| 候选方式 | 适用条件 | 优点 | 风险 |
|---|---|---|---|
| A. `argmax` 等级 | ModernBERT 六分类和二分类字段 | 简单、易解释 | 丢失置信度；两个相近 logit 与一个压倒性 logit得到相同等级 |
| B. softmax 后的期望等级/类别概率 | logits 的温度和类别顺序可信 | 连续、保留不确定性 | 不同模型 logits 未必校准；需只在训练折估计温度或直接报告未校准 |
| C. logit margin | 二分类 `fluency_en`、`ad_en` | 无需概率校准，方向明确 | 不同模型的 margin 尺度不可直接比较，仍需稳健缩放 |
| D. 域内分位数/稳健 Z 分数 | DSIR、RPS 结构指标 | 减少领域和极值影响 | 训练/验证必须分别按冻结规则变换，不能用验证集分位数 |
| E. 区间型效用 | 长度、熵、数字比例、词长等非单调字段 | 符合“过低和过高都可能不好” | 区间端点属于训练过程，必须在训练集冻结并做敏感性分析 |

### 1.5 冲突定义候选

| 冲突定义 | 怎么理解 | 适用条件 | 主要风险 |
|---|---|---|---|
| 方向冲突 | 两个已统一方向的指标对同一对文本给出相反排序 | 两指标都具有可信的单调质量方向 | DSIR、长度类指标不满足时会制造假冲突 |
| 高置信阈值冲突 | 某文本同时出现“至少一个强好信号”和“至少一个强坏信号” | 阈值只用训练数据冻结，并有校准/分位定义 | 阈值多、结论对阈值敏感 |
| 指标家族冲突 | 模型评价、目标相似度、文本结构、重复/噪声等家族的聚合意见相反 | 先处理同一家族强相关指标 | 家族划分和家族权重需人工说明 |
| 域条件冲突 | 在相同来源域和相近长度内，指标仍给出相反判断 | GitHub、arXiv、Wikipedia 等体裁差异明显时 | 小域样本少时分位不稳 |
| Pareto 冲突 | 一个文本在某些维度更好、另一些更差，双方都不支配 | 不愿预先给权重时 | 只能形成候选前沿，不能自动给唯一总分 |

**建议进一步检查**：三名队员分别用“家族+域条件”“概率/期望等级”“Pareto/不预设权重”做一版。先比较冲突样本的稳定性和下游 Loss 验证，再决定是否合成唯一 Q。当前不建议把 22 个原始字段直接 Min-Max 后等权平均。

### 2.3 候选划分方案与风险

1. **问题一文本层**：按 `id` 分组，再在训练部分保持 `_source_domain` 比例。风险是域间泛化没有单独评估。可加“留一来源域”压力测试。
2. **问题一配比层**：严格使用官方 A4–A15 角色，不自行把检验表混入调参。风险是 A4 只有 512 个配比，高维模型易过拟合。
3. **问题二轨迹层**：外层留模型尺度/模型族，内层只在剩余轨迹上调参。风险是尺度数仅 8 或 7，折数不能设得过多。
4. **问题四时间层**：按日期滚动回测，同时把同一基础模型家族整体放在时间允许的一侧。风险是严格家族隔离会减少样本，但比随机划分可信。

**建议进一步检查**：先生成一份机器可读 `split_manifest.csv`，包含 `record_id/group_id/time/source/role/fold`，三名队员都使用同一份划分。模型合并比较才有意义。

## 3. A、B 组 Loss 兼容性

### 3.1 需要确认的问题

- 两组是否使用相同验证文本、相同分词器、相同 token 平均方式、相同对数底和相同序列处理？
- A 的 13 域 Loss 应如何变成一个总体 Loss，权重从哪里来？
- 如果不兼容，如何把问一结果传给问二而不伪造共同量纲？

### 3.2 已知事实与兼容性证据

| 项目 | A 组 | B 组 | 当前判断 |
|---|---|---|---|
| Loss 结构 | A5/A7/A9/A11/A13/A15 每行有 13 个 `metric/the_pile_*_val_loss` | B1/B2/B4–B8/B10 每行一个 `val_loss` | **不等结构**：域向量对总体标量 |
| 验证集 | 字段名明确到 13 个 The Pile 子域；17 个训练域中有 4 个没有对应 Loss 列 | CSV 中没有验证集名称字段；Pythia 上游资料说明使用 The Pile，但本地表无法确认具体 split/是否 deduped | **不能确认相同验证集** |
| 分词器 | A 表无 tokenizer 字段；RegMix 上游训练框架与数据处理需要另行核对到具体配置 | B 表无 tokenizer 字段；Pythia 官方仓库使用 GPT-NeoX tokenizer，但本地 B1 无版本/哈希 | **不能确认本地两组完全相同** |
| Loss 定义 | 可见说明称交叉熵 Loss，但 CSV 无底数、mask、序列长度或 token 加权字段 | 可见说明称交叉熵；B1/B2 中 `ppl≈exp(val_loss)`，最大相对误差分别约 0.000611、0.000307，支持自然对数逐 token 口径 | B 内部口径证据较强；A 缺少等价核验 |
| 模型与训练制度 | RegMix 1M/60M/1B 及 10B/70B 外推，模型和配比实验 | Pythia/Cerebras 多尺度轨迹及跨族点 | 架构、训练过程和规模覆盖不同 |
| 数值范围 | A 真实训练/检验表约 0.8311–8.7156；外推表约 0.4964–2.9153 | B1/B2 的训练/验证 Loss 合计约 1.9430–6.5040；其他表另有不同范围 | 范围重叠不能证明可比 |

结论：**目前没有足够证据把 A、B Loss 逐行合并或用同一截距拟合。** “都是交叉熵”只说明公式家族相同，不保证评价数据、分词器、token 化、平均方式和模型族相同。

### 3.3 候选处理方式

| 方式 | 必须满足的条件 | 优点 | 风险 |
|---|---|---|---|
| A. 完全独立建模 | 无额外条件 | 最稳妥；问一学习配比→域 Loss，问二学习 N、D→B 的 val_loss | Q/p 与问二接口较弱，只能传趋势或标准化效应 |
| B. 源内标准化后传递效应 | 在每个来源内用训练集冻结基准，传递相对改善量或弹性，而非原始 Loss | 不要求绝对 Loss 同量纲 | 标准化会改变物理解释；基准选择影响结果 |
| C. 建立经验映射 | 需要一批同一模型、同一 checkpoint 同时在 A 验证集和 B 验证集评估的锚点；映射数据不能再当独立验证 | 能把 A 域 Loss 映射到 B 口径 | 当前附件没有这样的直接配对；小样本映射不稳定 |
| D. 分层/多任务模型 | 至少有跨来源重叠模型或可识别的共享尺度；为数据源设置截距、尺度和随机效应 | 可显式建模来源差异 | 没有锚点时共享潜变量不可识别，复杂模型会制造“统一”假象 |
| E. 只用 A 的某一域（如 Pile-CC）对接 | 必须确认 B 的验证集就是同一 Pile-CC 版本、同一 tokenizer 和同一 token 平均方式 | 简单清楚 | 当前证据不足；仅同名数据域仍可能版本不同 |

**建议进一步检查**：

1. 在 RegMix 配置或模型卡中定位 tokenizer 文件/哈希、验证集文件列表、序列长度、loss mask 和汇总方式。
2. 为 B1 的实际来源记录标准版/去重版 Pile、tokenizer 哈希和 validation split。
3. 若无法补齐，三人方案都应保持 A/B 独立；可以比较相对效应，不比较绝对 Loss 截距。

- 全量检查：`results/07_loss_compatibility_checks.csv`。
- 可见截图：第 5、6、9、10、11 页。
- RegMix 官方仓库说明其默认使用 Pile-CC 验证 Loss：[sail-sg/regmix](https://github.com/sail-sg/regmix)。

## 4. 半合成、插值和外推数据的边界

### 4.1 需要确认的问题

- 哪些数据是独立测量，哪些是已有模型的再计算产物？
- 某数据若用于生成/校准模型，能否又用来证明同一模型有效？
- 哪些结果只能称“敏感性分析”，不能称“外部验证”？

### 4.2 数据性质与允许用途

| 数据 | 性质 | 适合的用途 | 不允许的表述/用法 |
|---|---|---|---|
| A1–A3 | 公开语料上的模型评分与文本统计记录；文件层面是真实记录，但 22 个评分不是人工统一真值 | 构造质量特征、域内分布和冲突分析；用下游 Loss 间接验证 Q | 不能说成 22 个独立人工实验真值 |
| A4–A11 | RegMix 真实训练/检验配比与 Loss | A4/A5 拟合；A6–A11 按题面做独立检验和跨尺度检验 | 不能把检验表用于选阈值、选模型后仍称独立检验 |
| A12/A14 | A4 训练配比的 63 行子集 | 指定配比的跨尺度压力测试 | 不能称新配比独立验证 |
| A13/A15 | 10B/70B 外推 Loss | 外推敏感性、讨论不确定性 | 不能称真实 10B/70B 训练观测 |
| A16 | 人工整理参考映射 | 初始映射、敏感性候选 | 不能当客观唯一映射 |
| A17/A18 | 领域摘要与真实文本样例 | 域语义核查、重复检测、辅助构造质量域统计 | A18 抽样不能代替全部 RegMix 语料 |
| B1 | Pythia 真实轨迹 | 问二主拟合/轨迹验证，按整条轨迹分组 | 检查点不能当 1,176 次独立训练 |
| B2 | 真实标度规律校准后加噪的半合成轨迹 | 族外形式压力测试、噪声敏感性 | 不能作为对真实 Cerebras 轨迹的独立实证 |
| B3 | B1 检查点插值 | 曲线连续化、数值稳定和轨迹形状检查 | 不能与 B1 合并扩大样本量；不能作独立验证 |
| B4/B5 | 公开/文献收敛点 | 跨族或外部证据，前提是 Loss 口径兼容 | 不能忽略来源差异后直接池化 |
| B6/B7 | 半合成 N–D–Q 实验 | 探索 Q 项的可识别性、函数形式和敏感性 | B6 不能与包含它的 B7 重复计样本；不能证明真实 Q 效应 |
| B8 | 半合成大型矩阵；984 calibrated、720 extrapolated | 将校准区和外推区分开做敏感性/压力测试 | 与 B6/B7 相同 N–D–Q 点的 Loss 并不相同，不能视作同一数据集追加 |
| B9 | 大模型公开元数据，部分训练量/算力为公开估计 | 定义现实规模范围、元数据趋势 | 估计值不能称精确训练测量 |
| B10 | 大模型估算 Loss | 极端尺度压力测试 | 不能参与主参数拟合后又作为独立大模型验证 |
| B11/B12 | 模型族与 checkpoint 元数据 | 实体连接、分组和复现核查 | 不能作为新的性能观测 |
| C1/C2/C8/C9 | 排行榜和评测运行的真实观测记录 | 问四能力度量、时间回测、逐任务聚合 | 同一模型重复提交/多次评测不能当独立模型 |
| C3 | 榜单与历史资料混合时序 | 长期趋势，必须保留来源标签 | 不同来源机制不能静默当同一随机样本 |
| C4/C7 | 架构与训练元数据 | 控制规模/架构、上下文情景 | 缺失不能填成 0；公开估计不能当精确真值 |
| C5/C6 | 混合来源 Loss–Benchmark 桥接；仅 7 条 High 可比 | 分层桥接、删一敏感性、区间估计 | 不能只凭全部样本训练拟合度声明桥接可靠 |

### 4.3 避免循环论证的最低规则

1. 用于选择 Q 公式或权重的数据，不能再被称为 Q 的独立验证。
2. 用半合成生成规律拟合出的模型，不能再用同一半合成表证明“发现了真实规律”。
3. 插值点只能检查数值曲线，不能增加有效样本量。
4. 外推值只能测试模型在既定外推机制下的行为，不能证明现实大模型遵循该结果。
5. 任何主结论至少需要一个未参与模型/阈值选择的真实数据验证层；若做不到，应把结论降级为“模型内情景”。

**建议进一步检查**：要求三名队员在每个结果表旁增加 `evidence_level`：`real_holdout / real_observational / semi_synthetic / interpolated / extrapolated / metadata`。合并方案时不得删除这一列。

## 5. C9 与 C1

### 5.1 需要确认的问题

- 是否值得为 C9 安装解析依赖？
- C9 的额外列是否会被问四实际使用？
- C1 的清洗是否删除了可能需要的实体匹配、架构或评测元数据？

### 5.2 已知事实

**C9 本地文件完整**：`train-00000-of-00001.parquet` 为 1,109,997 字节，CRC32 为 `b95be810`，SHA-256 为 `f13a7061e63133bc8745d89f8c7a56148584940ede22d3b27e21cad1e078dca5`。无法读取不是文件损坏，而是当前项目 Python 没有任何 Parquet 引擎：`pyarrow=False`、`fastparquet=False`，同时也没有可替代的 `duckdb` 或 `polars`。

此前从腾讯镜像安装失败的原因是网络/代理不可用，不是包代码报错。修复有三种方式：

| 方式 | 代码成本 | 环境成本 | 风险 |
|---|---:|---:|---|
| 安装 `pyarrow` | 很低；现有 `pandas.read_parquet` 无需改结构 | 需要匹配 Python 3.10/Windows 的二进制 wheel；当前网络需恢复或离线传入 | 包体和磁盘占用较大，但兼容性通常最好 |
| 安装 `fastparquet` | 很低；同样可由 pandas 调用 | 需要 `fastparquet` 及其二进制依赖 | 对嵌套类型支持通常不如 pyarrow；本表是扁平表，风险较低但仍需验证 |
| 在另一台有 Parquet 环境的机器导出只读 CSV/Arrow schema | 中等；需记录原文件哈希、导出脚本和行列校验 | 不改比赛机环境 | 转换过程可能改变类型/空值表示；必须保留原 C9 和校验日志 |

工程上属于“单依赖安装 + 重跑字段审计”，不是复杂开发；当前真正成本是获取可信 wheel，而不是写代码。

### 5.3 C1 和 C9 的差异

| 方面 | C1 `leaderboard_cleaned.csv` | C9 原始 Parquet | 对用途的影响 |
|---|---|---|---|
| 行数 | 4,576 | 可见说明和官方 schema 均为 4,576 | 核心记录数相同，不应重复计样本 |
| 列数 | 12 | 36 | C9 保留更多原始评测和模型元数据 |
| 核心字段 | Model、参数量、提交日、许可证、类型、Average、六项规范化得分 | 包含同一核心字段 | 只做六维得分与时间趋势时，C1 信息基本够用 |
| 原始分数 | 不保留 `Raw` 列 | 含 IFEval/BBH/MATH/GPQA/MUSR/MMLU-PRO 的 Raw 与规范化列 | 分析归一化影响、复算 Average 时 C9 更重要 |
| 模型/运行元数据 | 精简 | 还包括 precision、architecture、model sha、可用性、MoE、flagged、chat template、CO₂、merged、official provider、generation、base model 等 | 实体去重、模型族控制、评测异常和架构分层时 C9 更有价值 |
| 可读性 | CSV 可直接审计 | 当前缺 Parquet 引擎 | C1 可以先用于原型，但不能据此宣称 C9 没有增量价值 |

C9 的 36 列结构可由 Open LLM Leaderboard 官方 [contents 数据卡](https://huggingface.co/datasets/open-llm-leaderboard/contents/blob/main/README.md)核对；可见截图第 12 页也明确说明其“核心六维与 C1 等价，另含原始附加列，任选其一”。

### 5.4 候选处理方式

1. **问四只分析六维 Benchmark 与时间/规模**：可先用 C1，但要记录“未使用 C9 的原始分数和额外元数据”，不能把 C1 称为 C9 的完全等价副本。
2. **需要复算 Average、检查归一化、做模型族/架构/重复提交控制**：应修复 C9 解析，优先离线安装匹配版本的 `pyarrow`。
3. **时间来不及修环境**：在另一台可信环境把 C9 转为 CSV，同时输出 schema、行数、列数、哈希和 C1 核心列逐行一致性检查，再复制到 `_tmp/` 或 `results/`；原 Parquet 保持只读。

**建议进一步检查**：先由问四的三份独立方案列出实际需要的字段。只要任一方案需要 Raw 分数、Base Model、Architecture、Merged、Flagged、Chat Template 或 Model sha，就不应直接放弃 C9。
