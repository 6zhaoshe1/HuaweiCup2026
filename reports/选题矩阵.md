## 2. 逐题判断与打分理由

### A 题：通用神经网络处理器下的多核调度问题

题面链条是“DAG 划分为子图 → 分配到 2–5 个核并排序 → 处理跨核同步/片上复用 → 增加共享只读 L2 Cache”，核心指标是 Makespan，并伴随 DDR 搬运、缓存命中等评价。

- **数据 9**：100 个真实计算图 JSON，字段、单位、容量和评估配置清楚；附件带 10 个 Python 评估/辅助脚本、算法说明与固定配置，能快速建立基线。
- **建模 8**：图划分、多机调度、通信代价、缓存复用和多目标权衡都能展开，但题型以算法工程为主，统计建模空间相对窄一些。
- **代码 8**：必须维护“划分—分配—排序—合法性—评估”的完整闭环，并在最大约 3.87 万操作、10.83 万边的图上稳定运行。
- **算力 5**：主要是 CPU 图算法和反复模拟，不需要训练大模型；但批量评估与参数搜索仍会耗时。
- **验证 5**：官方评估器让可行性和指标验证明显容易；难点是无法轻易证明全局最优，只能用强基线、下界、消融和多实例稳定性说明。
- **创新 8**：可在通信感知图划分、关键路径优先、增量局部搜索、缓存感知调度、跨实例自适应启发式上创新。
- **论文 8**：问题递进清楚，适合写算法框架、复杂度、可行性证明、基线、消融和规模分析；若只有“调参后更快”，论文会显得工程化。
- **风险 7**：无效拓扑、内存峰值、跨核依赖、共享带宽和缓存统计任一处理错误都会整体失分；局部指标提升不必然降低 Makespan。
- **适配 8**：非常贴合计算机专业，且不要求深度学习经验；需要较强的数据结构、算法和性能调优能力。

### B 题：氢燃料电池低温冷启动建模与控制策略研究

四问从单电池一维瞬态多相机理模型，推进到 5 电池堆自启动、电辅助加热和多初始状态动态反馈控制。

- **数据 7**：参数表和 `-20℃/-25℃` 两组 0.2 s 级实验数据字段清楚，但只覆盖有限温度与实验条件，复杂模型的可辨识信息偏少。
- **建模 9**：传热、气液冰三相、水迁移、电化学反应、PDE/DAE、控制与多目标优化空间很大。
- **代码 10**：需要可靠的空间离散、刚性时间积分、事件/相变处理、参数标定、控制仿真和优化；任何一层不稳都会向后传递。
- **算力 8**：单次高保真仿真可能已较慢，外层策略搜索再嵌套仿真会显著增加成本。
- **验证 9**：两组实验既要标定又要验证，很容易同源验证；还要做网格/步长收敛、守恒、参数可辨识性和边界条件敏感性。
- **创新 9**：降阶、物理约束代理、可辨识参数化、鲁棒/MPC 控制都能创新，但实现门槛高。
- **论文 9**：若模型正确，公式、机理、校准、策略和敏感性非常好写；若数值闭环不稳，篇幅反而暴露漏洞。
- **风险 10**：单位、符号、相变潜热、含水量边界、冰堵判据、堆内一致性和“模型内最优”误写为现实最优，均是高危点。
- **适配 3**：缺少燃料电池/传热/数值 PDE 背景时，计算机专业与 ML 新手很难在竞赛时间内完成可信闭环。

### C 题：服务于脑机接口与精神性疾病诊断的脑电图计算模型

三块任务是：针对视觉任务的脑电去噪与响应提取；构造 LGN—皮层—头皮机制模型并解释左右三角差异；再加入海马等认知环节并验证。

- **数据 8**：4 个 MAT 记录、10 通道、256 Hz，时长约 14.5–15 min，字段与形状清楚；但有效独立单位少，且题面明确部分机器滤波通道不可直接使用。
- **建模 9**：信号处理、事件相关响应、源—传导机制、神经动力学和认知模型都能展开。
- **代码 7**：去噪、事件切片、频时分析和曲线拟合不算重；机制模型、参数标定及统一验证会明显抬高工作量。
- **算力 4**：经典信号处理、状态空间或小型动力系统用普通 CPU 即可，不需要大模型。
- **验证 10**：仅靠 F3/Fz/F4 与少量记录去验证 LGN、海马和精神疾病机制，识别性很弱；同一连续记录切片若跨折会产生严重泄漏。
- **创新 9**：机制约束去噪、层级状态空间、跨任务共享机制、可识别性与不确定性分析都有空间。
- **论文 8**：图谱、时频响应和机制示意丰富；但最难的是让机制结论与观测证据真正对应。
- **风险 10**：把相关/拟合写成脑区因果机制、用同一记录切片做随机验证、过度解释注意力或频段差异，都会形成科学性硬伤。
- **适配 6**：信号处理对计算机专业友好，但神经生理、机制辨识和实验设计门槛高于一般 ML 分类题。

## 3. 推荐结论

### 首选：F 题

选择理由：不需要真实训练大语言模型，数据丰富且大多为结构化表格/日志；四问有一条非常顺的论文主线；计算机专业能够理解数据语义，ML 新手也能从透明基线做起。最大的挑战是外推、重复记录和因果措辞，而这些可以通过冻结验证协议、留模型族验证、情景预测和不确定区间控制。

首轮应坚持的简化路线不是复杂模型，而是：质量信号清洗与冲突审计 → 可解释质量分基线 → 对数/分层回归的 scaling 基线 → 约束下可复核的网格或标准优化 → 滚动回测与情景区间。只有透明基线不够时再升级。

### 备选：A 题

选择理由：与计算机专业非常匹配，附件含完整评估闭环，往年还有高度相似的优秀论文可参考；不用 GPU，也不依赖行业机理。它比 F 更偏算法竞赛，代码强度更高，但结果可被官方评估器直接验证，适合队内有人擅长图算法、调度与性能优化的情况。

### 条件备选：E 题

只有在满足“可用 GPU/依赖环境稳定 + 至少一人能维护 PyTorch/多模态训练 + 接受较长实验时间”时保留。否则它会把大量时间消耗在特征抽取、显存、依赖和复现实验上，性价比低于 F/A。

### 不作为前两名

- **D 题**：数据最好、论文也最好写，但四问耦合最重，GIS、装箱/VRP、连续通信优化和分组都要落地；很容易得到“图很漂亮、约束未闭合”的方案。
- **C 题**：算力不高，但科学验证最困难；题目要求的 LGN/皮层/海马机制远超三导联头皮 EEG 能稳健识别的范围，容易在因果与生理解释上失分。
- **B 题**：机理、数值 PDE、参数辨识和控制均为高门槛，有限实验条件难以验证复杂模型；对当前“计算机专业 + ML 新手”的组合最不友好。

## 4. 需要队伍人工确认的问题

1. 本机/队伍可用硬件：CPU 核数、内存、是否有 NVIDIA GPU、显存及比赛期间能否持续占用；这决定 E 是否保留，也影响 A 的批量评估速度。
2. 三名队员实际能力分工：是否有人熟悉图算法/运筹优化、PyTorch、多模态处理、数值 PDE 或 GIS；请按“能独立写并调通”而不是“学过”回答。
3. 比赛剩余时间与目标偏好：优先稳健完成并冲奖，还是愿意为高创新承担实现风险；当前推荐默认按稳健完成排序。
4. 题目目录是否还会追加官方补充说明、修订附件或新的评测脚本；尤其 A 的评估口径、E/F 的数据说明需要在最终选题前冻结版本。
5. F 题是否允许比赛期间联网补查模型发布时间/公开基准信息，以及最终提交是否对外部数据、代码依赖和附件大小有额外限制；若不允许，应只使用题给数据并在论文中明确边界。
6. 若选 F：是否接受对第 4 问只给“情景预测 + 不确定区间”，不做无法验证的单点断言；若选 A：是否接受先做确定性启发式与强基线，不把深度强化学习作为起点。

## 5. 最终建议

在当前已知条件下直接定题：**F 题**。如果队内确认更擅长算法工程、对统计外推没有把握，则切换到 **A 题**。只有 GPU 和多模态经验都确认可用，才把 **E 题**提到备选位；B、C 放弃，D 留作“队内已有成熟运筹/GIS 代码库”时的特殊选项。
